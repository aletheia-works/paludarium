# アーキテクチャ

paludarium は、役割ごとに分けた crate でできています。依存は上から下への一方向だけで、
循環はありません。

| 層 | 使う層 |
|---|---|
| 入口（`paludarium` コマンド、Rust の API、WebAssembly の launcher） | runtime |
| runtime | cpu、jit、kernel、loader、host |
| cpu、jit | decoder、mmu |
| kernel | mmu、vfs、loader、host |
| loader | mmu、vfs |
| vfs | host |

すべての crate が、`paludarium-types` の共通の型を使います。

## crate

| crate | 役割 |
|---|---|
| `paludarium-types` | 共通の型（`GuestAddr`、`Errno`、`ExitReason`、`ExitStatus`、`Error`） |
| `paludarium-decoder` | iced-x86 を包んだデコーダ。外には自前の命令の型だけを出す |
| `paludarium-mmu` | ソフトウェア MMU。4 KiB のページの 2 段のページテーブル |
| `paludarium-host` | ホストとの境界（`Host` trait）と、Linux・macOS・Windows・WebAssembly の実装 |
| `paludarium-vfs` | メモリ上の安全なファイルシステムと、ホストのディレクトリのマウント |
| `paludarium-loader` | ELF と、それが求めるインタプリタの読み込みと、最初のスタック（argv・envp・補助ベクタ） |
| `paludarium-cpu` | x86-64 のインタプリタ |
| `paludarium-jit` | コードキャッシュの口と、WebAssembly 向けの JIT |
| `paludarium-kernel` | Linux のシステムコール。プロセスとスレッドの状態を持つ |
| `paludarium-runtime` | `Session` と、スレッドごとの実行ループ |
| `paludarium` | 公開の API と `paludarium` コマンド |

公開していない crate が 2 つあります。`paludarium-harness` は差分テストの道具、
`paludarium-wasm` は npm パッケージの `paludarium.wasm` になる WebAssembly の入口です。

## 実行の流れ

1. Loader が ELF を読み込み、メモリに置いて、最初のスタックを作ります。
2. 実行ループが CPU に命令を実行させます。JIT が有効なら、先にコードキャッシュに
   変換済みのブロックがあるかを聞き、なければインタプリタで実行します。
3. CPU は、システムコールやゲストの例外に当たると、止まった理由を返して止まります。
   CPU は Kernel を知りません。
4. 実行ループが Kernel を呼んでシステムコールを処理するか、ゲストにシグナルを送ります。
5. 実行ループは、10 万命令ごとに、外から止めるよう求められていないかを確かめます。

スレッドのレジスタの状態は Kernel が持ち、CPU は渡された状態を実行するだけです。

インタプリタは、スレッドごとのデコードキャッシュにデコードした命令を持ち、命令を、それを含むブロックごとに
一度だけデコードします。ブロックは、その番地から、メモリの上で続いている命令を `jmp`、`call`、`ret`、
`syscall`、`hlt`、`ud2` まで、または 32 命令まで並べたものです。条件分岐ではブロックは終わりません。
インタプリタがブロックを引くのは、次の命令が今のブロックの次の命令でないとき、つまり分岐、システムコール、
fault の後、ブロックの終わり、コードの世代が進んだときだけです。ある命令から次の命令へそのまま進むときは
何も引きません。

コードの世代は、アドレス空間ごとのカウンタです。マッピングが変わったとき（`mmap`、`munmap`、`mprotect`、
`mremap`）、そのアドレス空間がコードを実行しうる共有マッピングやページキャッシュに、どれかのプロセスか Kernel が
書き込んだとき、そして、命令を取り出したことのある実行可能なページに、そのアドレス空間が書き込んだときに進みます。
ページごとに、命令を取り出したことがあるかどうかの印を持ちます。印は外さず、コピーオンライトや `fork` で
ページをコピーしても引き継ぎます。何も取り出していない実行可能なページへの書き込みは世代を進めないので、
デコードした命令を古くしません。SBCL のヒープは読み書きも実行もできるページで、以前はそこへ書き込むたびに、
インタプリタがすべてをデコードし直していました。ページから初めて命令を取り出すときは、アドレス空間のロックを
取り、TLB のエポックを進めてから印を付けます。エポックを進めると、ロックなしで途中にある書き込みを待ちます。
そのため、書き込みが印を見て、バイトを書いた後で世代を進めるか、取り出しがそのバイトを見るかのどちらかに
なります。

ブロックは最初の命令だけで始まり、実行するにつれて伸びます。ブロックの最後の命令のすぐ後に実行する命令は、
ブロックが無いときと同じく一つだけでデコードし、そのブロックの後に別のブロックが入っていなければ、そこに足します。
そのため命令をデコードするのは初めて実行するときだけで、デコードできない命令が fault を出すのも、
ブロックが無いときと同じく、そこまで実行が来たときだけです。

キャッシュが持てる命令の数はスロットの数までで、写しも数えます。ブロックの途中への分岐は別のブロックを始め、
最初のブロックの残りをもう一度デコードするからです。いっぱいになったとき、今の世代のブロックが半分を超えていれば
大きさを倍にし、そうでなければブロックを全部捨てます。どちらでも何もコピーしません。JIT のようにコードをよく
変えるプログラムは、前の世代のブロックで何度もいっぱいにするからです。

デコードのときには、よく出る単純な形（`nop` と `endbr64`、レジスタとメモリの間の mov、
メモリからの `movzx`、`lea`、`push` と `pop`、直接の分岐、`call`、`ret`、レジスタに対する
`add`、`sub`、`and`、`or`、`xor`、`cmp`、`test`、メモリに対する `cmp` と `test`）も
決めておきます。オペランドを前もって取り出しておくので、実行するときにニーモニックによる
汎用の振り分けも、汎用のオペランド処理も通りません。こうした形は、失敗しうることを全部済ませてから
状態を変えます。失敗したときは何も変わっていないので、同じ命令を汎用の経路で実行し直し、
そちらが fault を報告します。そのため 2 つの経路の意味は同じで、すべての形について
ランダムな状態からそれを確かめる単体テストがあります。
キャッシュは、この形と次の命令の番地と 2 つのフラグ（64 バイトのキャッシュライン 1 本に収まります）を、
汎用の経路だけが読むデコードした命令そのものとは別に持ちます。そのため、こうした形が続くあいだに読む
ホストのメモリは少なくて済みます。

## ホストとの境界

ネイティブと WebAssembly の違いは、`paludarium-host` の中だけに閉じ込めています。
ほかの crate は、`std::thread`・`std::fs`・`std::time` を直接は呼びません。
`Host` trait が出すのは、スレッドの起動、待機と起床、時計、期限つきの待機、端末の情報、
標準入出力、安全な乱数、ホストのディレクトリのマウントです。

ゲストのシステムコールの番号、ゲストのポインタ、ゲストの `ioctl` の番号は、
この境界を越えません。

## エラーの 3 つの種類

型で分けています。

| 種類 | 型 | 行き先 |
|---|---|---|
| システムコールの失敗 | `Errno` | ゲストに errno として返す |
| ゲストの例外 | `ExitReason` | ゲストへのシグナル（`SIGSEGV`、`SIGBUS`、`SIGILL`、`SIGFPE` など） |
| エミュレータ自身の問題 | `Error` | 命令のアドレス・バイト列・システムコールの番号を添えて止まる |

ゲストの終了（`ExitStatus`）とエミュレータのエラーは混ぜません。

## 安全のための決まり

- `unsafe` を使ってよいのは、ホストとの接続部と JIT だけです。それ以外の crate は
  `#![forbid(unsafe_code)]` です（今は JIT も `unsafe` を使っていません）。
- 製品のコードでは、`unwrap`・`expect`・`panic` を clippy で禁止しています。
- ゲストのアドレス（`GuestAddr(u64)`）とホストのアドレスを型で分けています。
  WebAssembly では `usize` が 32 bit なので、境界の変換はすべて検査します。
