# アーキテクチャ

paludarium は、役割ごとに分けた crate でできています。依存は上から下への一方向だけで、
循環はありません。

| 層 | 使う層 |
|---|---|
| 入口（`paludarium` コマンド、Rust の API、WebAssembly の launcher） | runtime、jit-native |
| runtime | cpu、jit、kernel、loader、host |
| jit-native | cpu、decoder、mmu |
| cpu、jit | decoder、mmu |
| kernel | mmu、vfs、loader、host |
| loader | mmu、vfs |
| vfs | host |

すべての crate が、`paludarium-types` の共通の型を使います。

## crate

| crate | 役割 |
|---|---|
| `paludarium-types` | 共通の型（`GuestAddr`、`Errno`、`ExitReason`、`ExitStatus`、`Error`） |
| `paludarium-decoder` | iced-x86 を包んだデコーダ。外には自前の命令の型だけを出す |
| `paludarium-mmu` | ソフトウェア MMU。4 KiB のページの 2 段のページテーブル |
| `paludarium-host` | ホストとの境界（`Host` trait）と、Linux・macOS・Windows・WebAssembly の実装 |
| `paludarium-vfs` | メモリ上の安全なファイルシステム、ホストのディレクトリのマウント、マウント名前空間ごとのマウントの表 |
| `paludarium-loader` | ELF と、それが求めるインタプリタの読み込みと、最初のスタック（argv・envp・補助ベクタ） |
| `paludarium-cpu` | x86-64 のインタプリタ |
| `paludarium-jit` | コードキャッシュの口と、WebAssembly 向けの JIT |
| `paludarium-jit-native` | ネイティブの JIT。よく実行されるブロックを Cranelift でホストのコードにする |
| `paludarium-kernel` | Linux のシステムコール。プロセスとスレッドの状態を持つ |
| `paludarium-runtime` | `Session` と、スレッドごとの実行ループ |
| `paludarium` | 公開の API と `paludarium` コマンド |

公開していない crate が 2 つあります。`paludarium-harness` は差分テストの道具、
`paludarium-wasm` は npm パッケージの `paludarium.wasm` になる WebAssembly の入口です。

## 実行の流れ

1. Loader が ELF を読み込み、メモリに置いて、最初のスタックを作ります。
2. 実行ループが CPU に命令を実行させます。JIT が有効なら、先にコードキャッシュに
   変換済みのブロックがあるかを聞き、なければインタプリタで実行します。
3. CPU は、システムコールやゲストの例外に当たると、止まった理由を返して止まります。
   CPU は Kernel を知りません。
4. 実行ループが Kernel を呼んでシステムコールを処理するか、ゲストにシグナルを送ります。
5. 実行ループは、10 万命令ごとに、外から止めるよう求められていないかを確かめます。
   サンプリングする `cpu-clock` か `task-clock` がスレッドを数えているあいだは、クロックが
   次に発火するころに、ただし 5,000 命令は走ってから、実行を区切ります
   （`Kernel::run_budget`）。

スレッドのレジスタの状態は Kernel が持ち、CPU は渡された状態を実行するだけです。

インタプリタは、スレッドごとのデコードキャッシュにデコードした命令を持ち、命令を、それを含むブロックごとに
一度だけデコードします。ブロックは、その番地から、メモリの上で続いている命令を `jmp`、`call`、`ret`、
`syscall`、`hlt`、`ud2` まで、または 32 命令まで並べたものです。条件分岐ではブロックは終わりません。
インタプリタがブロックを引くのは、次の命令が今のブロックの次の命令でないとき、つまり分岐、システムコール、
fault の後、ブロックの終わり、コードの世代が進んだときだけです。ある命令から次の命令へそのまま進むときは
何も引きません。WebAssembly JIT を使うときも、ループは同じようにブロックをたどり、
命令を実行する前にそれぞれ JIT に渡します。ただし、ブロックがキャッシュにある間に JIT が断った命令は、
もう渡しません。

コードの世代は、アドレス空間ごとのカウンタです。マッピングが変わったとき（`mmap`、`munmap`、`mprotect`、
`mremap`、`brk`、`shmat`、`shmdt`）、`MADV_DONTNEED` の `madvise` がプライベートなページか共有のページのエントリーを捨てたとき、
そのアドレス空間がコードを実行しうる共有マッピングやページキャッシュに、どれかのプロセスか Kernel が
書き込んだとき、命令を取り出したことのある実行可能なページに、そのアドレス空間が書き込んだとき、そして
それ以外にページが変わったときに進みます。スタックが下へ伸びたとき、`MADV_GUARD_INSTALL` がページにガードを
置いたとき、`UFFDIO_MOVE` がページを動かしたとき、ファイルの切り詰めで末尾より後ろになったページのプライベートな
コピーが再びファイルを見せるとき、`fork` が `MADV_DONTFORK` や `MADV_WIPEONFORK` の領域と、fault で
埋め直すページを子に渡さないときがそれです。
ページごとに、命令を取り出したことがあるかどうかの印を持ちます。印は外さず、コピーオンライトや `fork` で
ページをコピーしても引き継ぎます。何も取り出していない実行可能なページへの書き込みは世代を進めないので、
デコードした命令を古くしません。SBCL のヒープは読み書きも実行もできるページで、以前はそこへ書き込むたびに、
インタプリタがすべてをデコードし直していました。ページから初めて命令を取り出すときは、アドレス空間のロックを
取り、TLB のエポックを進めてから印を付けます。エポックを進めると、ロックなしで途中にある書き込みを待ちます。
そのため、書き込みが印を見て、バイトを書いた後で世代を進めるか、取り出しがそのバイトを見るかのどちらかに
なります。

アドレス空間は、Linux の RSS のカウンタと同じく、持っているページ（`VmRSS`）も数えます。数は、変わった
ページのエントリーとともに変わります。fault でページがエントリーを得たとき、プライベートなページが初めての
書き込みで自分のバイトを得たとき、unmap・`madvise`・`mremap` がエントリーを取り除いたり動かしたりしたときです。
そのため、ページを捨てる前ごとに記録する最大値（`VmHWM`）の費用は、捨てる範囲のページテーブルの分だけで、
アドレス空間全体の分ではありません。読み書きの費用は増えません。デバッグビルドは、数を読むたびと
アドレス空間がなくなるときに、すべてのエントリーと突き合わせます。

ブロックは最初の命令だけで始まり、実行するにつれて伸びます。ブロックの最後の命令のすぐ後に実行する命令は、
ブロックが無いときと同じく一つだけでデコードし、そのブロックの後に別のブロックが入っていなければ、そこに足します。
そのため命令をデコードするのは初めて実行するときだけで、デコードできない命令が fault を出すのも、
ブロックが無いときと同じく、そこまで実行が来たときだけです。

キャッシュが持てる命令の数はスロットの数までで、写しも数えます。ブロックの途中への分岐は別のブロックを始め、
最初のブロックの残りをもう一度デコードするからです。いっぱいになったとき、今の世代のブロックが半分を超えていれば
大きさを倍にし、そうでなければブロックを全部捨てます。どちらでも何もコピーしません。JIT のようにコードをよく
変えるプログラムは、前の世代のブロックで何度もいっぱいにするからです。

デコードのときには、よく出る次の単純な形も決めておきます。

- `nop` と `endbr64`
- レジスタとメモリの間の mov と、メモリからの `movzx`
- `lea`、レジスタ、即値またはメモリの 8 バイトの `push`、`pop`
- 直接の分岐、`call`、`ret` と、64 ビットのレジスタかメモリの 8 バイトを通した `jmp` と `call`
- レジスタ、即値、メモリの間の（`lock` なしの）`add`、`sub`、`and`、`or`、`xor`、`cmp`、`test` と、レジスタとレジスタか即値の `adc`、`sbb`
- レジスタの即値による `shl`、`shr`、`sar`、`rol`、`ror` と、レジスタの `cl` による `shl`、`shr`、`sar`
- レジスタからの `movzx`、レジスタまたはメモリからの `movsx` と `movsxd`、`cbw`、`cwde`、`cdqe`、16 ビットか 32 ビットのレジスタへの `lea`
- レジスタと（`lock` なしの）メモリに対する `inc`、`dec`、`neg`、`not`
- `setcc` と `cmovcc`
- レジスタから同じ大きさのレジスタへの `tzcnt`、`lzcnt`、`popcnt`、`bsf`、`bsr`、レジスタのレジスタか即値による `bt`、`bts`、`btr`、`btc`、32 ビットか 64 ビットのレジスタの `bswap`
- レジスタによる rdx:rax への `mul` と `imul`、rdx:rax のレジスタによる `div` と `idiv`、2 つのレジスタまたはレジスタと即値の `imul`
- xmm レジスタとメモリの間の `movaps`、`movups`、`movdqa`、`movdqu`、`movapd`、`movupd`、xmm レジスタどうしの `pxor` と `xorps`、xmm レジスタと汎用レジスタまたはメモリの間の `movd` と `movq`、xmm レジスタどうしの `movq`、xmm レジスタとメモリの間の SSE2 の `movsd`
- xmm レジスタどうしの `pshufd`、`pshuflw`、`pshufhw`、`punpckl` と `punpckh` の各アンパック、`packuswb`、`packsswb`、`packssdw`、`paddd`、`psubd`、`paddq`、`psubq`、`pmuludq`、`pand`、`por`、`pandn`、`pcmpeqb`、`pcmpeqw`、`pcmpeqd`、xmm レジスタと 16 バイトのメモリの `pxor` と `pcmpeqb`、即値による `pslld` と `psrld`、`pmovmskb`
- 64 ビットのアドレスの（`rep` ありまたはなしの）文字列の転送 `movsb`、`movsw`、`movsd`、`movsq` と、文字列の書き込み `stosb`、`stosw`、`stosd`、`stosq`
- メモリとレジスタの間の（`lock` ありまたはなしの）`cmpxchg` と `xchg`。どちらも、インタプリタと同じ 1 回のアトミックなメモリアクセスです

これらの形のレジスタは、上位バイトのレジスタ `ah`、`ch`、`dh`、`bh` でもかまいません。

これらの形のオペランドを前もって取り出しておくので、実行するときにニーモニックによる
汎用の振り分けも、汎用のオペランド処理も通りません。こうした形は、失敗しうることを全部済ませてから
状態を変えます。失敗したときは何も変わっていないので、同じ命令を汎用の経路で実行し直し、
そちらが fault を報告します。そのため 2 つの経路の意味は同じで、すべての形について
ランダムな状態からそれを確かめる単体テストがあります。
繰り返しの文字列命令は、1 ステップに最大 4096 回繰り返し、続きは次のステップで実行します。
比較でない繰り返しの文字列命令が、そのステップの 2 回目以降の繰り返しで fault を出すときは、
そこまでの繰り返しを済ませた状態でそのステップを終え、次のステップが fault を報告します。
CPU も `rep` を繰り返しの合間で止めることがあるからです。そのため、繰り返しの文字列の転送と書き込みも、
形が失敗したときは何も変えていません。
キャッシュは、この形と次の命令の番地と 3 つのフラグ（64 バイトのキャッシュライン 1 本に収まります）を、
汎用の経路だけが読むデコードした命令そのものとは別に持ちます。そのため、こうした形が続くあいだに読む
ホストのメモリは少なくて済みます。

## ネイティブの JIT {#the-native-jit}

`--jit` を付けると、デコードキャッシュのブロックのうち、よく実行されるものをホストの
コードにコンパイルします（`paludarium-jit-native`、x86-64 の Linux のホストだけ）。
ブロックは、入った回数を数えます。それがしきい値（既定は 300）に達すると、先頭の命令の形を、
形のない最初の命令の手前まで、コンパイラに渡します。JIT 専用のスレッドがそれを Cranelift の
IR にしてコンパイルし、書き込みと実行が同時にはできないメモリに置きます。コードができるまでと、
コンパイルに失敗したときは、インタプリタが今までどおりそのブロックを実行します。

コンパイルしたコードの意味は、インタプリタの形の意味とまったく同じです。スレッドのレジスタを、
インタプリタが置いているメモリの上でそのまま読み書きします（出し入れの写しはしません）。
揃った 1 ワードに収まる 8 バイトまでの読み書きは、スレッドの TLB がそのページを持ち、MMU が
コンパイルしたコードのために持つスロットがその読み書きを許すとき、ページのバイトを直接読み書きします。
スロットは埋めたときのエポックでだけ有効で、書き込みは MMU 自身の TLB 経由の書き込みが書くところにしか
許さず、命令を取り出したことのあるページには許しません。実行可能でもデータしか置いていないページ
（SBCL のヒープなど）は、そこから命令を取り出すまでスロットを通して書き込みます。
それ以外の読み書きと、スロットが許さないもの、たとえば
`mprotect`、`UFFDIO_WRITEPROTECT`、消えた soft-dirty ビットが守るページへの書き込みは、
MMU 自身の読み書きを呼ぶので、その検査もそのまま働き、スロットを埋め直します。
オペランドを読んでから書く命令の読み込みは、ページを書き込みとして求めるので、インタプリタと同じく
書き込みとして 1 回だけ fault します。
読み書きが失敗する命令の手前では、その命令について何も変えずに止まり、
インタプリタがその命令を実行し直して fault を報告します。MMU を呼んだ読み書きがコードの世代が
進んだのを見つけたときも、その後で止まります。fault（#DE）を出す `div` と `idiv` の手前でも、
同じように止まります。`rep movs` と `rep stos` はインタプリタと同じように実行します。4096 回繰り返したとき、
または 2 回目以降の繰り返しが失敗したときは、そこまでの繰り返しを済ませ、その命令を実行したものと数えて、
その命令の番地で抜けます。命令は次にもう一度実行されます。ページのバイトを直接読み書きしても世代は進みません。
スロットは命令を取り出したことのあるページへの書き込みも、共有やファイルのページへの書き込みも
許さないからです（MMU は、見張っている共有のマッピングとページキャッシュへの書き込みを
コードの変更として数えます）。その間にほかのスレッドが進めた世代は、次に MMU を呼んだとき、
またはブロックの後でインタプリタが世代を読み直したときに見えます。
分岐が成立したときと、`jmp`、`call`、`ret` で終わります。実行した命令の数を返し、
インタプリタはその次の命令から続けます。

コードの世代が進むと、インタプリタはすべてのブロックをデコードし直しますが、ほとんどは同じ形に
なります。JIT はコンパイルしたコードを形ごとに覚えておき（65536 ブロックまで）、形が同じ
ブロックには同じコードを渡します。そのため、メモリをよくマップするプログラムでも、何度も
コンパイルし直すことはありません。コードは、Session のすべてのスレッドとプロセスで共有します。
環境変数 `PALUDARIUM_JIT_STATS` を設定すると、コンパイルしたブロックと命令の数と、それに
かかった時間を標準エラーに出します。

## ホストとの境界

ネイティブと WebAssembly の違いは、`paludarium-host` の中だけに閉じ込めています。
ほかの crate は、`std::thread`・`std::fs`・`std::time` を直接は呼びません。
`Host` trait が出すのは、スレッドの起動、待機と起床、時計、期限つきの待機、端末の情報、
標準入出力、安全な乱数、ホストのディレクトリのマウントです。

ゲストのシステムコールの番号、ゲストのポインタ、ゲストの `ioctl` の番号は、
この境界を越えません。

## エラーの 3 つの種類

型で分けています。

| 種類 | 型 | 行き先 |
|---|---|---|
| システムコールの失敗 | `Errno` | ゲストに errno として返す |
| ゲストの例外 | `ExitReason` | ゲストへのシグナル（`SIGSEGV`、`SIGBUS`、`SIGILL`、`SIGFPE` など） |
| エミュレータ自身の問題 | `Error` | 命令のアドレス・バイト列・システムコールの番号を添えて止まる |

ゲストの終了（`ExitStatus`）とエミュレータのエラーは混ぜません。

## 安全のための決まり

- `unsafe` を使ってよいのは、ホストとの接続部と JIT だけです。それ以外の crate は
  `#![forbid(unsafe_code)]` です。WebAssembly 向けの JIT は、今は `unsafe` を使っていません。
  ネイティブの JIT が使うのは 1 つのモジュールだけで、そこでコンパイルしたコードをマップして
  呼び出します。そのコードは MMU を呼び返すか、スレッドの TLB に MMU が埋めるスロットが許すところでは、
  ゲストのページのバイトを自分で読み書きします。
- 製品のコードでは、`unwrap`・`expect`・`panic` を clippy で禁止しています。
- ゲストのアドレス（`GuestAddr(u64)`）とホストのアドレスを型で分けています。
  WebAssembly では `usize` が 32 bit なので、境界の変換はすべて検査します。
